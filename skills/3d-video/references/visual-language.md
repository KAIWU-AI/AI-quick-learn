# 从已验证演示提炼的视觉要点

## 保留的有效做法

- **一个持续存在的世界。**相机移动，不每几秒销毁重建一页；固定节点与相连路径保持身份。
- **按职责换造型。**客户端是显示器，服务是模块塔，数据是叠盘，执行器是分层芯片，权限是可通行的门，集群是中心模型与环绕计算单元，队列是排队槽，存储是容器。
- **材质有结构。**倒角、接触阴影、金属和漆面、CC0环境反射；木纹只用于指定group底板，不把场景铺满桌子。
- **信号是主体。**连续多段flow只有一个实体；路由和端点真实对应，返回路径单独画。绘制顺序不能偷偷改变拓扑。
- **标签不闪烁。**用距离、视口边缘的连续透明度，初始化烘焙60Hz缓动轨迹；播放/倒放/跳帧得到同一状态。不要用CSS transition修补一个不可确定的动画。
- **小标题、职责短注。**不强制双语、不贴每页大标题；中文标签使用随包字体，避免不同机器替换后溢出。
- **留白不是空洞。**light主题强调材质；space主题使用低速、固定随机分布的星轨，不盖过架构。
- **镜头有目的。**跟请求到处理器、跟结果回入口。最后保持完整架构2秒以上，不突然黑屏。

## 避免重蹈的失败

1. 只调颜色/缓动，却保留PPT翻页结构。
2. 所有模块变成相同圆角卡片；用“高级”代替实际材质。
3. 门柱挡住信号或到门口删除后重建。需看实际编码帧，不只检查`visible=true`。
4. 星空过密、过快、拖尾太长；背景应该从属于节点与流。
5. 把英文第二行和实现清单当作必需信息；让短句说职责。
6. 瞬时避碰选择不同位置导致标签跳动。位置轨迹需按固定时间预先计算并平滑。
7. 只验证浏览器截图，不看MP4；字体、WebGL和编码路径可能有差异。

参数建议：主要label26px，detail19px；相机俯角约0.35—0.75rad，移动2—4秒；流量颗粒不编码真实性能；最小节点间距5.5场景单位。复杂密集图先删节点，再放大画布，勿把字缩到不可读。
