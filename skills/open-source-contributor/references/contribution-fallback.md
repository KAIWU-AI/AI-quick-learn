# 贡献兜底：由主 Agent 评估本轮结果后启用

本页是课程指定的局部兜底，不是默认推荐，不参与随机候选池，也不是降低质量门槛的快捷方式。通用流程和扫描器不绑定任何学员、机器或本地工作区。

## 启用条件

决定权属于主 Agent。先汇总本轮所有仓库负责人的返回结果：调研过哪些仓库、技能和历史 PR，检查或验证过哪些 Issue，是否有修复/测试证据，哪些因政策、重复工作或环境受阻，以及尚未解决的读取错误。只有扫描推荐为空、一个 Issue 已修复或缺少标签，不等于子 Agent 已完成真实调研。

本轮所有负责人都已返回，且主 Agent 核实没有可继续推进的合格结果时，可以启用 HydraLab 兜底，不要求先遍历默认 30 个仓库，也不强制再运行多轮。主 Agent 结合证据、剩余时间和环境，选择继续通用发现或进入兜底，并记录理由。这里的判断仅针对已评估的本轮结果，不代表其他开源仓库都没有贡献机会。单 Agent 降级模式同样由主 Agent 对本轮实际调研结果作出评估，不伪造子任务返回。

仍有可行任务正在推进、交付包等待验证或已具备发布条件时，优先完成它们，不提前切换。对空报告、未结束任务和读取失败先核实真实状态；缺少证据不能直接推断无机会，通用的认证或网络阻塞也不会因为换仓库而自动消失。确实无法完成评估时报告评估未完成，而不是强行宣布满足兜底条件。

启用后由主 Agent 明确分配一个 HydraLab 负责人，继续执行调研技能/规则、学习历史 PR、查重、复现、实现、独立验证和授权发布流程；其他子 Agent 不自行转入同一仓库。保存原候选的证据与补丁，避免重复实现、重复 PR 或丢失已有工作。兜底也没有合格结果时如实报告未完成，不能继续放宽质量门槛。

## 指定仓库

课程指定兜底目标为 [`microsoft/HydraLab`](https://github.com/microsoft/HydraLab)。

这不代表项目预先认可课程提交，也不保证有现成可做的 Issue。每次进入时都应重新阅读：

- [贡献指南](https://github.com/microsoft/HydraLab/blob/main/CONTRIBUTING.md)
- [开发环境说明](https://github.com/microsoft/HydraLab/wiki/Dev-Environment-Setup)
- [开放 Issue](https://github.com/microsoft/HydraLab/issues)
- [开放与关闭 PR](https://github.com/microsoft/HydraLab/pulls)

以上分支链接是 2026-09-27 核对时的入口；实际工作前重新读取当前默认分支。仓库主体为 Java/Gradle，并非只需 Python。移动设备、Android/iOS、前端或完整服务部署都可能引入额外条件，不要把它描述成零环境成本的兜底。

## 寻找和验证

先核实贡献政策、AI 使用规则、CLA 和账号权限，再查重和复现。优先考虑无需设备或生产服务即可验证的独立逻辑、已有测试，以及会导致用户执行错误命令的安装说明或可执行示例。只做实际发现的问题，不能预先声称这些区域一定有缺陷。

代码变更必须能运行相关项目原生测试。Java 变更需要匹配的 JDK 和 Gradle 环境，Windows 使用仓库的 `gradlew.bat`，其他平台按贡献指南使用 wrapper；具体任务从当前构建配置确认，不猜模块或测试命令。文档变更也应验证原命令确实存在问题、修改后的命令确实可用，不能用拼写或格式调整冒充修复。

学员之间应分配不同问题，不要把同一问题拆成重复 PR。已有活跃实现时换目标；不要为了“必发 PR”批量发认领评论或提交无关练习文件。

## 发布和完成条件

沿用主 Skill 的授权、最小修复、回归测试、审查和远端回读流程，以及 [`pr-workflow.md`](pr-workflow.md) 中的发布步骤。确认目标是指定的上游，而不是误向自己的 fork 提交后声称完成上游贡献。

教学交付必须包含真实 PR 地址、远端 head SHA、变更文件和 CI 状态。创建后跟进维护者反馈；不得承诺合并，不得绕过项目的 CLA 或 AI 使用政策。

GitHub 认证受到 SSO 限制时，公开只读读取可以帮助研究，但不能证明 fork、push 或创建 PR 有权限。权限不足、无合规问题或无法验证时，明确报告未完成及具体阻塞，请讲师协调维护者认可的任务或环境；不能自动换到未授权仓库、降低门槛或伪造成功。
