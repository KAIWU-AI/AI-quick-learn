# Demo 2：让模型记住前面的对话

**本课只增加一个概念：历史上下文。** Demo 1 每次只发送一个问题；这次把用户消息和助手响应保存到列表，下一轮一起发送。没有工具，也不是 Agent Loop。

先按[根目录配置](../README.md#三个-ai-基础-demo)安装依赖，在仓库根目录运行：

```bash
python -m demo2
python -m demo2 "记住我的练习代号是蓝鲸17。" "刚才的练习代号是什么？"
python -m demo2 --interactive --max-turns 6
python -m demo2 --output demo2/result.html
```

默认演示三轮：先提供虚构练习代号、学习目标和每日时间，再询问前面的信息，最后基于这些信息制定计划。观察第二、三轮没有重复交代背景，模型仍可从传入的历史中找到它。

## 可视化看板

每次运行自动生成 `demo2/result.html`，用浏览器直接打开，无需启动服务器。用 `--output` 自定义路径。页面随每个观测事件更新；交互聊天期间刷新即可看到新增轮次。

- **结果与总览**：最后一轮回答、此前各轮回答、请求次数、已报告的输入/输出 token 总量、耗时。
- **调用路径与逐步回放**：用户输入 → 模型请求 → 模型返回 → 保存历史 → 助手回答。点击轮次卡片、时间线、上一步/下一步或进度条定位；播放只回放已有记录，不会再次请求 API。
- **记忆如何增长**：显示每次写入前后的 history 项数和完整快照，以及每轮实际发送的 input。`reasoning` 项也计入历史，**项数不等于消息轮数或 token 数**。
- **请求与返回树**：原始嵌套对象、数组、字段类型与说明都可展开查看。可以筛选模型、记忆或异常事件。

`/reset` 在时间线上明确显示历史从多少项变成 0；之前的观测记录仍保留，以便对照，但不会重新传给模型。失败时页面保留已经获得的回答和部分轨迹，并明确标注失败，不将失败轮次写入记忆。运行配置失败也会生成错误报告；命令仍以非零状态退出。

报告是离线 HTML；播放与节点高亮不是模型内部思维链。`encrypted_content` 已遮蔽，不影响真实请求中完整历史的回传。报告仍包含输入与回答，不要公开敏感内容。默认报告已加入 `.gitignore`，自定义输出路径请自行排除。

```text
第 1 轮：[用户 1]                         → 助手 1
第 2 轮：[用户 1, 助手 1, 用户 2]         → 助手 2
第 3 轮：[用户 1, 助手 1, 用户 2, 助手 2, 用户 3] → 助手 3
```

实际 `history` 还可能包含 `reasoning` 项，不能只保留图中的文本。打开 `__main__.py` 看 `chat_turn`：本轮成功后保存完整 `response.output`；下轮的 `input` 包含历史和新问题。`store=False` 配合 `reasoning.encrypted_content` 保留推理模型的可回传状态，不打印或解读加密内容。

这不是模型权重学会了你，也不是长期记忆、数据库或自动检索。记忆来自**当前进程中的列表**；退出或 `/reset` 后即清空。历史越长，后续请求的输入 tokens 通常越多。

交互模式支持 `/reset` 和 `/exit`；默认最多 6 次 API 请求，清空记忆不会重置预算。API 失败、响应不完整或没有文本时明确报错，不把失败轮次写入历史。

## 动手做个对照

在交互模式中先提供一个虚构代号，再询问它；然后输入 `/reset`，再次询问。比较“携带历史”和“清空历史”的差别。不要使用真实个人资料。

第三课在这个历史列表上增加工具请求、工具执行结果和自动继续的循环，也就是 Agent Loop。
